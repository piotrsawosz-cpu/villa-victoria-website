## Phase 3 — PLANNED, NOT STARTED

**Goal:** make the multilingual content actually rankable in DE/FR/ES markets (which the ad campaigns target) by giving each language its own crawlable URL, and replace the in-browser Babel/JSX rendering with built/pre-rendered HTML.

**Why this matters:**
- Currently `website/index.html` loads React + Babel from CDN (lines 33–35) and JSX-transforms in the browser → Googlebot can render JS but it's slow and unreliable for a content site.
- `website/components/i18n.js` switches EN/ES/FR/DE via `localStorage` only → Google sees only the English version. DE/FR ad audiences land on a page Google has never indexed in their language.

**Recommended approach:** migrate to **Astro + @astrojs/react** with i18n routing. See full reasoning in `~/.claude/plans/how-can-i-make-wiggly-babbage.md` § Phase 3.

### Key architectural decisions (already made)

| Decision | Choice |
|---|---|
| Framework | **Astro** (over Next.js — lighter, built for content sites; over Vite SSG — better i18n routing) |
| URL structure | Subdirectory: `/`, `/es/`, `/fr/`, `/de/` (not subdomains) |
| Default language at root | English (with `hreflang="x-default"`) |
| Sitemap | Auto-generated by `@astrojs/sitemap`, one entry per language with hreflang alternates |
| Branch strategy | **Work on `feat/astro-migration` branch with Vercel preview URL — do not touch `main` until tested** |
